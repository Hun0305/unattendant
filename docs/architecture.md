## 개요

라즈베리파이 한 대가 블로그 서버와 실행 노드를 맡고, Claude가 주제 선정부터 작성, 발행, 성과 분석, 주간 회고까지 결정하는 **무인 운영 블로그**를 만든다. 사람은 지켜보고 필요할 때만 개입한다.

**이름**: 블로그는 `unattendant.dev`, 에이전트는 **Huninn**이다. unattendant는 un + attendant(당번)로 "자리에 없는 당번"이고, Huninn은 북유럽 신화에서 매일 날아가 보고 들은 것을 보고하는 오딘의 까마귀 Huginn(생각)과 Muninn(기억)을 합친 이름이다. 이름이 뜻을 다 설명하지 않으므로 최상단에 태그라인을 둔다.

- **영어**: *unattendant — the attendant who isn't there. A blog run by Huninn, an AI living on a Raspberry Pi.*
- **한국어**: *unattendant — 자리에 없는 당번. 라즈베리파이 위에서 AI 'Huninn'이 혼자 운영하는 블로그.*

디스코드 봇 이름과 주간 보고서 서명도 Huninn을 쓴다.

- **메타 컨셉 (정체성)**: "AI가 혼자 블로그를 운영한다"는 실험 자체를 공개한다. 주간 보고서, 전략 변경, 실패 기록이 그대로 콘텐츠가 되고, 커뮤니티에 공유할 이야기를 맡는다.
- **Pi 실측 데이터 (검색 유입)**: Pi가 직접 벤치마크와 측정을 돌리고 그 데이터로 글을 쓴다. 같은 실험을 매달 다시 돌려 시계열로 쌓고 원본을 공개한다. 검색으로 찾아오는 독자는 이쪽이 맡는다.
- **언어**: 한국어가 메인이고, 주간 보고서와 실험 글은 영어판도 낸다. 해외 커뮤니티와 링크드인 독자를 위한 것이다.
- **수익과 활용**: 계정을 팔지 않는다. 광고·제휴(광고 표시 포함)는 부가 수익이고, 핵심 가치는 포트폴리오다.

**성공 기준**

1. 사람 개입 없이 4주 이상 연속 운영한다.
2. 운영 지표(개입 횟수, 장애 자동 복구, 글당 비용)가 처음부터 기록된다.
3. 검색엔진에 색인되고, 실험 글 1개 이상이 외부 커뮤니티나 AI 검색에서 인용된다.

유사 사례와 포지셔닝 근거는 시장 조사 탭에 정리했다.

## 설계 원칙과 제약

모든 선택은 "차단될 수 있는 것을 피하고, 남는 것을 기록한다"는 기준을 따른다.

| 원칙 / 제약 | 내용 |
| --- | --- |
| 공식 API만 사용 | 네이버·티스토리는 글쓰기 API가 종료됐다. 브라우저 매크로는 계정 제재 리스크가 있어 메인 채널에서 제외한다. |
| 무인 운영 우선 | 모든 단계는 실패를 감지하고 재시도하거나 사람에게 알린다. 조용히 멈추는 상태는 허용하지 않는다. |
| AI 운영 공개 | 모든 글에 AI 작성임을 표시한다. 컨셉이자 스팸 판정을 피하는 장치다. |
| 하드웨어 | Pi 4B 4GB와 64GB SD카드로 시작한다. DB가 필요해지거나 용량이 부족하면 보유한 1TB 외장 SSD로 복제한다. 노트북(i5-8250U, 16GB)은 필요할 때만 켜는 실험 장비로 쓴다. |
| 비용 | 고정비는 도메인 연 1\~2만 원 + LLM API 사용료. 터널·CDN·호스팅은 무료 플랜 안에서 해결한다. |
| LLM 호출 | 24시간 무인 호출은 구독 사용량이 아니라 API 키로 하고, 월 예산 상한을 둔다. |
| 관측 가능성 | 모든 툴 호출과 결정을 로그로 남긴다. 포트폴리오 지표의 원천이다. |

## 기술 스택 선택지

결정할 건 세 가지다. 블로그를 어디서 무엇으로 돌릴지, 도메인을 어떻게 공개할지, Claude를 어떤 방식으로 호출할지. 각각 3안을 비교한다.

### A. 블로그 엔진과 호스팅

| 안 | 구성 | 장점 | 단점 |
| --- | --- | --- | --- |
| A1. Hugo + git, Pi에서 서빙 | AI가 마크다운 작성 → git commit → Pi에서 Hugo 빌드 → Caddy가 정적 HTML 서빙 → Cloudflare Tunnel | DB가 없어 가볍고 SD카드로 충분하다; git이 곧 백업이자 버전 관리다; 레포를 GitHub에 공개하면 포트폴리오가 된다; 글이 파일이라 AI가 다루기 쉽다; "Pi가 서버까지 운영"하는 메타 스토리가 살아있다 | 댓글·구독은 외부 서비스(giscus, RSS 메일 등)를 붙여야 한다; 빌드·배포 파이프라인을 직접 만든다; Pi가 죽으면 블로그도 내려간다 |
| A2. Ghost, Pi에서 서빙 | Docker로 Ghost + MySQL 실행 → AI가 Admin API로 발행 → Cloudflare Tunnel | 발행·태그·뉴스레터·멤버십이 내장돼 있다; 에디터 UI로 사람이 바로 고칠 수 있다; REST API가 잘 정리돼 MCP로 감싸기 쉽다 | Node + MySQL이 상주해 무겁다(RAM 1GB 이상 권장); DB 쓰기가 잦아 SSD가 사실상 필수다; DB 덤프 백업을 따로 돌려야 한다; 코드 공개 포트폴리오 성격이 약하다 |
| A3. Hugo + git, Cloudflare Pages에서 서빙 | AI가 마크다운 작성 → GitHub에 push → Cloudflare Pages(또는 GitHub Pages)가 자동 빌드·배포. Pi는 에이전트와 실험만 담당 | Pi가 죽어도 블로그는 살아있다; 무료이고 CDN이 빠르다; push가 곧 배포라 파이프라인이 가장 단순하다 | "Pi가 서버"라는 메타 스토리가 약해진다; 서버 운영 지표(업타임, 장애 복구)라는 포트폴리오 소재가 줄어든다 |

### B. 도메인과 공개 방식

| 안 | 구성 | 장점 | 단점 |
| --- | --- | --- | --- |
| B1. Cloudflare Registrar + Named Tunnel | Cloudflare에서 도메인 구매, DNS와 Tunnel을 한 계정에서 관리 | 도메인을 원가에 팔고 갱신비도 같다; 네임서버 위임 같은 절차가 없다; 관리 지점이 한 곳이다 | .kr 같은 국내 도메인은 못 산다; 해외 결제 가능한 카드가 필요하다 |
| B2. 국내 등록기관 구매 + Cloudflare DNS + Named Tunnel | 가비아 등에서 구매하고 네임서버만 Cloudflare로 바꿈 | .kr / .co.kr을 쓸 수 있다; 원화 결제와 한글 지원이 된다 | 첫해 할인 후 갱신비가 오르는 경우가 많다; 관리 지점이 두 곳으로 나뉜다 |
| B3. 도메인 없이 Tailscale Funnel | `이름.xxx.ts.net` 고정 URL을 무료로 받음 | 비용이 0원이다; 바로 시작할 수 있다 | 커스텀 도메인을 못 쓴다; URL이 블로그답지 않고 검색 노출·공유에 불리하다; 도메인을 나중에 바꾸면 쌓인 색인을 잃는다 |

Quick Tunnel(`trycloudflare.com`)은 URL이 실행마다 바뀌어 개발·테스트에만 쓴다.

### C. 에이전트 런타임 (Claude 호출 방식)

| 안 | 구성 | 장점 | 단점 |
| --- | --- | --- | --- |
| C1. Claude Agent SDK + 자체 MCP 서버 | Pi에서 Python 오케스트레이터가 Agent SDK로 루프를 돌리고, 블로그 툴은 MCP 서버로 제공 | 툴 호출·루프·컨텍스트 관리를 SDK가 맡는다; 같은 MCP를 Claude 데스크톱에도 붙여 사람이 수동으로 운영할 수 있다; MCP 설계 경험이 포트폴리오로 남는다 | SDK 내부 의존성이 더 무겁다(Pi ARM64에서 설치·메모리 확인 필요); 내부 동작을 세밀하게 제어하기 어렵다 |
| C2. Messages API 직접 호출 + 자체 tool-use 루프 | Python으로 루프를 직접 짠다. 툴 로직은 MCP 서버와 공유하는 라이브러리로 분리 | 가장 가볍다; 재시도·비용 상한·로깅을 완전히 제어한다; 토큰 비용 추적이 정확하다 | 루프, 컨텍스트 관리, 에러 처리를 직접 구현해야 한다 |
| C3. Claude Code headless (`claude -p`) + cron | cron이 프롬프트를 던지고, MCP는 설정 파일로 연결 | 하루 만에 돌려볼 수 있다; 코드가 거의 필요 없다 | 결과 파싱과 실패 감지가 약하다; 구독 인증으로 무인 운영하면 사용량 한도에 걸리므로 API 키가 필요하다; 엔지니어링 어필 포인트가 적다 |

## 권장 조합

**A1 + B1 + C2(프로토타입은 C3)** 을 권장한다. 시작 비용은 도메인비와 API 사용료뿐이고, 보유한 Pi와 SD카드로 바로 시작할 수 있다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 블로그 | A1. Hugo + git, Pi에서 서빙 | SD카드로 버티고, GitHub 공개 포트폴리오가 되고, 메타 스토리가 산다. A3와 소스가 같아서 Pi 장애 시 Cloudflare Pages를 대기 미러로 바로 돌릴 수 있다 |
| 도메인 | B1. Cloudflare Registrar | DNS·Tunnel·도메인이 한 곳에 있고 갱신비가 원가다. .kr이 꼭 필요하면 B2로 바꾼다 |
| 런타임 | C2. Messages API + 자체 루프 | Pi에서 가장 가볍고, 비용 상한과 장애 처리를 직접 통제해 무인 운영 지표를 정확히 남길 수 있다. 초기 1\~2주는 C3로 흐름만 검증한다 |

핵심은 **툴 로직을 한 라이브러리(`blogops`)로 만들고, MCP 서버와 C2 루프가 같이 가져다 쓰는 것**이다. 그러면 자동 운영은 C2가, 사람의 수동 개입은 Claude 데스크톱에 MCP를 붙여서 하고, 런타임을 C1으로 바꿔도 툴은 그대로다.

## 하드웨어와 리소스 예산

보유한 **Raspberry Pi 4B 4GB를 그대로 메인 서버로 쓴다.** Claude는 API로 부르고 블로그는 정적 HTML이라 평소 메모리 사용량은 1\~1.5GB 수준이고, 빠듯해지는 건 로컬 LLM 실험 때뿐이다.

OS는 다시 설치하지 않고 기존 Raspberry Pi OS 64비트(Debian 13 trixie)를 그대로 쓴다. 같은 Pi에서 돌던 TrueETA(키오스크 포함)는 꺼두었고, 이 상태에서 SSH만 붙였을 때 메모리 사용량은 414MB였다(2026-10-06 실측). 이미 설치된 cloudflared와 Tailscale은 재사용한다.

### 메모리 예산 (추정)

| 구성 요소 | 메모리 |
| --- | --- |
| OS + Tailscale (콘솔 부팅 기준, 데스크톱 포함 실측 0.4GB) | 200MB 안팎 |
| Caddy + cloudflared | 100MB 안팎 |
| 에이전트 루프 + MCP 서버 (Python) | 200\~300MB |
| 운영 대시보드 (FastAPI) + 디스코드 봇 | 150\~200MB |
| SSH 접속 | 수 MB |
| 사람이 접속해 쓰는 Claude Code | 300\~500MB |
| Hugo 빌드 (몇 초 동안) | 100\~300MB |
| **평소 합계** | **1\~1.5GB (2.5GB 이상 여유)** |
| 로컬 LLM 실험 (3B, 4비트 양자화) | 2\~3GB |

Pi 4 4GB에서 OpenClaw가 메모리 부족으로 멈춘 [사례](https://travis.media/blog/running-openclaw-headless-mac.md)는 Pi 안에서 의미 검색을 돌렸기 때문이다. 이 설계에는 그런 작업이 없다.

### 실험 중에도 SSH와 블로그를 지키는 설정

- **OS 정리**: 콘솔 부팅으로 바꿔 데스크톱(labwc, 패널 등 200\~300MB)을 끄고, Samba·PackageKit·Bluetooth도 끈다. 보안 업데이트는 unattended-upgrades로 받되 자동 재부팅은 하지 않고, 재부팅이 필요하면 디스코드 #일일요약으로 알린다.
- **스왑**: 디스크 스왑 대신 zram을 쓴다. 현재 스왑(2GB)이 zram인지 SD 파일인지 `swapon --show`로 확인해 필요하면 바꾼다.
- **포트**: 블로그용 Caddy는 8080에 띄워 다른 프로젝트 포트(TrueETA 8099 등)와 겹치지 않게 한다.
- **실험 격리**: 실험은 별도 systemd 서비스로 돌리고 메모리 상한(MemoryMax)을 건다. 한도를 넘으면 실험만 종료된다.
- **SSH 보호**: SSH 서버의 OOM 우선순위를 낮춰 메모리가 모자라도 마지막까지 살아남게 한다.
- **실험 규칙**: 로컬 LLM은 1\~3B 4비트 모델까지, 야간에 돌리고, 그동안 에이전트 루프는 쉰다.
- **캐시**: Cloudflare에서 HTML까지 캐시해, Pi가 바쁘거나 잠깐 내려가도 블로그는 열리게 한다.
- **냉각**: 방열판과 팬이 달린 케이스를 쓴다. 장시간 부하 때 스로틀링을 막고, 온도 기록은 그대로 실험 데이터가 된다.

### 노트북은 보조 실험 장비

2018년 노트북(i5-8250U, GeForce MX150, 16GB)은 24시간 서버로 쓰지 않고, 필요할 때만 켜는 실험 장비로 쓴다. 같은 모델을 Pi 4, x86 CPU, MX150 GPU에서 돌려 비교하는 글을 쓸 수 있다.

- **상시 서버로 쓰지 않는 이유**: 8년 된 배터리를 24시간 완충 상태로 두면 부풀 위험이 있고, 오래된 기기라 팬 소음과 열이 크며, "Pi에서 AI가 운영한다"는 정체성이 약해진다.
- **원격 켜기**: 유선 랜과 Wake-on-LAN을 지원하면 Pi가 실험 때만 노트북을 깨우게 할 수 있다. 지원 여부는 아직 확인하지 않았다.

### 전력과 전기요금 (추정)

| 장비 | 평균 전력 | 연간 전기요금 |
| --- | --- | --- |
| Pi 4B (+SSD) | 3\~5W | 약 4천\~1.6만 원 |
| 노트북 (덮개 닫고 대기 위주) | 8\~15W | 약 1만\~4.8만 원 |

kWh당 약 150\~360원으로 계산했다. 2026년 주택용 누진 1\~3단계 요금에 기후환경·연료비조정요금, 부가세, 전력기금을 더한 값이다([요금표](https://glasswallet.com/calculate/electricity-bill/progressive-rate/)). 차이는 월 몇천 원 수준이라, 장비를 고르는 기준은 전기세보다 배터리 안전, 소음, 정체성이다.

## 운영 사이클

에이전트는 일간·주간·월간 루프를 돈다. 발행 목표는 주 3개(실험 1, 메타 1, 주간 보고서 1)이고, 하루 최대 1개를 넘지 않는다. 실험 글과 주간 보고서는 영어판도 함께 내고, 두 언어판은 글 1개로 센다. 발행량보다 운영이 끊기지 않는 게 우선이다.

실험은 시간이 걸리므로 비동기로 돌리고, 결과가 나오면 다음 사이클에서 글로 쓴다.

### 일간 루프

1. **상태 점검**: 서버, 디스크 용량, 터널 연결, API 잔액, 도메인 만료일과 갱신 결제 수단, 지난 실패 내역을 확인한다. 이상이 있으면 복구부터 한다.
2. **지표 수집**: 어제 조회수, 유입 경로, 검색 노출을 가져온다.
3. **기획**: 전략 문서, 백로그, 완료된 실험, 지표를 보고 오늘 쓸 글을 고른다. 쓸 게 없으면 쓰지 않는다.
4. **실험 예약**: 새 실험이 필요하면 등록된 실험 템플릿 중에서 골라 예약한다.
5. **초안 작성**: 마크다운 초안과 메타데이터(태그, 요약, 출처)를 만든다.
6. **품질 게이트**: 수치가 실험 데이터와 일치하는지, 기존 글과 중복되지 않는지, AI 표시와 출처가 있는지 검사한다. 통과하지 못하면 최대 2회 고치고, 그래도 안 되면 보류하고 알린다.
7. **승인**: [todo.md](todo.md) 로드맵의 승인 모드 해제 기준(게이트 3)을 만족할 때까지는 사람이 승인해야 발행한다. 그 뒤에는 자동 발행으로 바꾸고 사후 알림만 보낸다.
8. **발행**: git commit → Hugo 빌드 → 배포 → 공개 URL 외부 접속 확인 → IndexNow 색인 요청 → 네이버·커뮤니티용 공유 문구를 공유 대기열에 넣는다.
9. **기록**: 이번 사이클의 결정, 툴 호출, 토큰 비용을 로그에 남긴다.

### 주간 루프 (일요일)

1. 한 주 지표와 운영 로그를 집계한다.
2. 주간 보고서를 글로 쓰고 발행한다. 메타 컨셉의 주력 콘텐츠다.
3. 전략 문서(`strategy.md`)를 고친다. 무엇을 그만두고 무엇을 더 할지, 그 근거를 남긴다.
4. 예산 사용량을 점검하고 다음 주 한도를 정한다.

### 월간 루프 (매월 첫 주)

1. 기준 실험(로컬 LLM 토큰 속도, 온도, 전력 등)을 같은 조건으로 다시 돌린다.
2. 결과를 시계열 CSV에 추가하고, 원본과 측정 조건을 공개 레포에 올린다.
3. 기존 실험 글을 새 데이터로 갱신하고, 변경 이력을 글 끝에 남긴다.

### 알림: 디스코드 봇

알림과 승인은 Pi에서 상시 실행하는 디스코드 봇(`discord.py`, systemd 서비스)으로 처리한다. 봇이 디스코드로 먼저 연결을 여는 방식이라 포트포워딩이 필요 없다.

- **#긴급**: 발행 실패, 빌드 실패, 예산 초과, 디스크 부족. 멘션과 함께 즉시 보낸다.
- **#승인**: 승인 대기 초안의 미리보기와 승인·반려 버튼. 버튼은 운영자 디스코드 계정 ID만 누를 수 있다.
- **#일일요약**: 발행 완료, 실험 결과, 공유 대기열을 하루 한 번 묶어서 보낸다.
- **외부 감시**: Pi가 죽으면 봇도 알리지 못하므로, 외부 업타임 모니터(UptimeRobot 등)의 알림을 같은 서버의 웹훅으로 받는다.

봇이 멈추면 승인이 들어오지 않아 발행도 멈춘다. 잘못 발행되는 것보다 안전한 동작이고, systemd가 봇을 자동으로 다시 띄운다. 봇 토큰은 `.env`에만 둔다.

## MCP 툴 스펙

MCP 서버 `blog-mcp`는 5개 영역 20개 툴을 제공한다. 셸 실행 같은 범용 툴은 두지 않고, AI는 정해진 툴로만 시스템을 건드린다.

권한은 세 단계다. **read**는 자유롭게 호출한다. **write**는 호출할 때마다 로그에 남는다. **gated**는 선행 조건(품질 통과, 승인)을 서버가 직접 검사하고, 충족하지 못하면 거부한다.

| 영역 | 툴 | 입력 | 출력 | 권한 |
| --- | --- | --- | --- | --- |
| 관측 | `get_system_health` | 없음 | CPU 온도, 디스크 여유, 업타임, 서비스 상태, 마지막 빌드 결과, 터널 연결, API 잔액, 도메인 만료까지 남은 일수, 디스코드 봇 상태 | read |
| 관측 | `get_site_stats` | 기간 | 조회수, 상위 글, 유입 경로 | read |
| 관측 | `get_search_stats` | 기간 | 검색 노출수, 클릭수, 유입 검색어 (Search Console) | read |
| 기획 | `get_strategy` | 없음 | 현재 전략 문서 | read |
| 기획 | `update_strategy` | 변경 내용, 근거 | 새 버전 번호 | write |
| 기획 | `list_posts` | 필터(태그, 기간) | 글 목록(슬러그, 제목, 날짜, 조회수) | read |
| 기획 | `search_posts` | 검색어 | 유사한 기존 글 (중복 확인용) | read |
| 기획 | `get_trends` | 소스 목록 | 키워드 후보와 출처 (RSS, GeekNews, HN 등) | read |
| 기획 | `manage_backlog` | 추가/수정/삭제, 항목 | 백로그 목록 | write |
| 실험 | `list_experiments` | 없음 | 등록된 실험 템플릿과 파라미터 범위 | read |
| 실험 | `schedule_experiment` | 템플릿 ID, 파라미터, 반복 주기(선택) | 작업 ID | write |
| 실험 | `get_experiment_result` | 작업 ID | 상태, 측정 데이터(CSV 경로), 요약 통계 | read |
| 발행 | `create_draft` | 제목, 본문(마크다운), 태그, 출처, 실험 ID, 언어(ko/en), 번역 묶음 키 | 초안 ID | write |
| 발행 | `check_quality` | 초안 ID | 통과 여부, 문제 목록 | read |
| 발행 | `request_approval` | 초안 ID | 승인 요청 ID (디스코드 #승인에 버튼과 함께 게시) | write |
| 발행 | `publish_post` | 초안 ID | URL, 커밋 해시 | gated |
| 발행 | `unpublish_post` | 슬러그, 사유 | 결과 | gated (사람 승인 필수) |
| 발행 | `request_indexing` | URL 목록 | IndexNow 응답 | write |
| 보고 | `queue_naver_digest` | 슬러그 | 네이버·커뮤니티·링크드인(영어)용 요약과 공유 문구 (대시보드 공유 대기열에 등록) | write |
| 보고 | `notify_human` | 수준(info/warn/critical), 메시지 | 전송 결과 | write |

주간 보고서는 별도 툴 없이 위 툴들로 만든다. 집계는 `get_site_stats`와 `get_search_stats`, 작성은 `create_draft`, 발행은 `publish_post`를 쓴다.

### 예시: `publish_post`

```json
{
  "name": "publish_post",
  "description": "품질 게이트를 통과한 초안을 발행한다. 승인 모드에서는 승인된 초안만 발행된다.",
  "input_schema": {
    "type": "object",
    "properties": {
      "draft_id": { "type": "string" }
    },
    "required": ["draft_id"]
  }
}
```

서버 쪽 검사 순서는 다음과 같다.

1. 초안의 마지막 `check_quality` 결과가 통과인지 확인한다. 그 뒤 본문이 바뀌었으면 거부한다.
2. 승인 모드면 승인 여부를 확인한다.
3. 오늘 발행 한도(1개)를 넘었는지 확인한다.
4. git commit → Hugo 빌드 → 배포하고, 빌드가 실패하면 커밋을 되돌리고 에러를 반환한다.
5. 공개 URL을 외부에서 요청해 응답 코드와 제목을 확인한다. 확인되지 않으면 발행 실패로 기록하고 알린다. 에이전트가 "완료"라고 보고했지만 실제로는 깨져 있던 사례(Agent Minerva)를 막기 위한 단계다.

실험은 미리 등록한 템플릿(예: CPU 벤치마크, 로컬 LLM 토큰 속도, 온도·스로틀링 측정)만 실행한다. AI가 임의의 명령을 만들지 못하게 하기 위해서다.

## 저장소, 백업, 노출

모든 원본은 git 레포 하나에 모으고, Pi가 죽어도 `git clone`과 설치 스크립트 하나로 복구되게 한다.

### 디렉터리 구조

```
~/unattendant/       # 운영 레포 Hun0305/unattendant (공개)
├── site/            # Hugo 사이트 (ko /, en /en/) → 사이트 레포 Hun0305/unattendant.dev (공개, 별도)
├── agent/           # Huninn 루프, blogops, MCP 서버, 디스코드 봇, 대시보드
├── experiments/     # 실험 템플릿과 결과 CSV
├── state/           # strategy.md, 백로그
│   ├── drafts/      #   미발행 초안 (git 제외)
│   └── approvals/   #   승인 상태 (git 제외)
├── logs/            # 툴 호출·결정·비용 원본 로그 JSONL (git 제외)
├── docs/            # 설계·계획 문서
└── ops/             # systemd 유닛, cloudflared 설정, 설치 스크립트, pre-commit 훅
```

레포는 두 개이고 **둘 다 공개한다**. `site/`는 사이트 레포로 따로 관리하고, 나머지는 운영 레포 하나로 묶는다. 코드는 시스템이 어떻게 동작하는지를, 커밋 히스토리와 가공한 운영 지표는 실제로 그렇게 돌았는지를 보여준다. 코드만 공개하면 "N주 무인 운영"은 확인할 수 없는 주장으로 남는다.

**비공개로 두는 것은 비밀값, 원본 로그, 미발행 초안 세 가지뿐이다.**

| 비공개 대상 | 경로 | 비공개인 이유 |
| --- | --- | --- |
| 비밀값 | `.env`, `~/.cloudflared/`, `~/.ssh/` | API 키, 봇 토큰, 터널 자격증명, deploy key |
| 원본 로그 | `logs/` | 툴 호출 결과나 에러에 키·디스코드 ID 같은 식별자가 섞일 수 있다. 식별자를 뺀 가공 지표만 공개한다 |
| 미발행 초안 | `state/drafts/`, `state/approvals/` | 품질 게이트와 승인을 아직 통과하지 않은 글과 그 승인 기록 |

이 경로들은 운영 레포 `.gitignore`(`site/`도 포함)로 git에서 빼고, Pi와 백업에만 둔다. `git add -f`로 우회해도 pre-commit 훅이 경로를 보고 막고, 내용 속 키 패턴은 gitleaks가 막는다([pre-commit.md](pre-commit.md)). 같은 Pi의 다른 프로젝트 폴더(Pi\_Server, TrueETA 등)는 건드리지 않는다.

### 백업

| 대상 | 방식 | 주기 |
| --- | --- | --- |
| 글, 실험 결과, 전략 문서, 코드 | GitHub에 push (글은 사이트 레포, 나머지는 운영 레포) | 발행·변경할 때마다 |
| 원본 로그, 미발행 초안 | git에 올리지 않고 압축해서 SanDisk USB에 보관 | 매일 |
| 시스템 전체 | SD카드 이미지 (SSD 이전 전에도 사용) | 달마다 |
| API 키, 토큰 | git에 올리지 않고 `.env`로만 보관, 별도 안전한 곳에 사본 | 변경할 때 |

SD카드 수명을 위해 디스크 스왑 대신 zram을 쓰고 log2ram을 설치한다. Ghost나 DB를 붙이거나 용량이 부족해지면 1TB 외장 SSD로 복제한다.

### 노출

- **검색엔진 등록**: Google Search Console, 네이버 서치어드바이저, Bing Webmaster Tools에 사이트맵을 제출한다.
- **IndexNow**: 발행 직후 `request_indexing`이 색인을 요청한다. 네이버와 Bing이 지원한다 ([GeekNews](https://news.hada.io/topic?id=19225)).
- **AI 크롤러 허용**: Cloudflare는 새 도메인에서 AI 크롤러를 기본으로 차단한다 ([CNBC](https://www.nbcnewyork.com/news/business/money-report/web-giant-cloudflare-to-block-ai-bots-from-scraping-content-by-default/6321598/)). AI 검색에 인용되려면 이 설정을 풀고 `robots.txt`에서도 허용한다.
- **AI 요약 인용 대비**: 네이버 AI 브리핑이 통합검색 질의의 20%까지 확대돼 클릭 유입이 줄고 있다 ([ZDNet](https://zdnet.co.kr/view/?no=20260805173711)). 글마다 핵심 수치와 측정 조건을 첫 문단과 표에 명시해 AI 요약에 출처로 인용되기 쉽게 한다.
- **신뢰 신호**: 실험 글마다 측정 방법, 장비, 원본 CSV 링크를 붙이고, 소개 페이지에 운영자(사람)를 명시한다.
- **다국어**: 한국어는 루트(`/`), 영어는 `/en/` 경로로 나눈다(Hugo 다국어 기능). 헤더의 언어 전환 버튼은 같은 글의 다른 언어판으로 보내고, 영어판이 없는 글에서는 숨긴다. 브라우저 언어로 자동 리다이렉트하지 않고, 영어판이 있으면 "English version available" 배너만 띄운다. 두 버전은 hreflang으로 서로 연결한다. 번역보다는 같은 데이터와 개요로 언어별로 따로 쓰고, 품질 게이트도 언어별로 돌린다.
- **배포 채널**: 네이버 블로그에는 요약과 원문 링크를 사람이 직접 올린다(주 1\~2회). 주간 보고서나 실험 글은 GeekNews, Reddit(r/raspberry\_pi, r/selfhosted) 같은 커뮤니티에, 영어판은 링크드인에도 공유한다. 공유는 처음부터 사람 몫으로 두고, 대시보드의 공유 대기열에서 처리한다. 링크드인은 자동 게시를 붙이지 않는다.

## 관측성과 포트폴리오 지표

대시보드는 조회수보다 **무인 운영 지표**를 중심으로 보여준다. 모든 지표는 `logs/`의 JSONL에서 계산되므로, 처음부터 로깅만 제대로 해두면 나중에 언제든 다시 집계할 수 있다.

| 지표 | 정의 | 출처 |
| --- | --- | --- |
| 연속 무인 운영일 | 마지막 사람 개입 이후 지난 일수 | 개입 로그 |
| 사람 개입 횟수 | 수동 승인을 제외한 수동 조작·수정 횟수 | 개입 로그 |
| 장애 자동 복구율 | 감지한 장애 중 사람 없이 복구된 비율 | 상태 점검 로그 |
| 품질 게이트 통과율 | 첫 초안이 바로 통과한 비율, 수정 후 통과한 비율 | `check_quality` 로그 |
| 글당 비용 | 글 1개를 만드는 데 쓴 토큰 비용 | API 응답의 usage |
| 업타임 | 외부에서 측정한 사이트 가용률 | 외부 모니터링(UptimeRobot 등) |
| 노출·유입 | 조회수, 검색 노출, 유입 경로별 비중 | Cloudflare Web Analytics, Search Console |

이 지표들이 모이면 이력서에 "엣지 디바이스 기반 AI 에이전트를 N주간 무인 운영, 사람 개입 N회, 장애 자동 복구 N건, 글당 비용 N원" 같은 문장을 쓸 수 있다.

### 대시보드

- **비공개 운영 대시보드**: Pi에서 가벼운 웹 페이지(FastAPI + 정적 HTML)로 로그를 집계해 보여준다. 승인 대기 초안, 네이버·커뮤니티 공유 대기열, 알림 이력도 여기서 처리한다. 공유는 사람이 주 1회 처리한다. 접근은 Tailscale이나 Cloudflare Access로 나만 들어가게 막는다.
- **공개 현황 페이지**: 블로그 안에 "AI 운영 현황" 페이지를 두고 연속 운영일, 글 수, 이번 주 전략을 매일 갱신한다. 메타 컨셉을 보여주는 장치다. 모든 페이지 상단에도 연속 무인 운영일, CPU 온도, 오늘 비용을 띠로 표시하고, 수치는 Pi가 몇 분마다 갱신하는 status.json에서 읽는다.
- Grafana는 설치·관리할 게 늘어나고 지금 규모에는 과하다. 지표가 늘어나면 그때 검토한다.

## 리스크와 가드레일

가장 큰 리스크는 틀린 내용을 자동으로 발행하는 것과, 루프 오류로 비용이 폭주하는 것이다. 두 가지 모두 프롬프트가 아니라 서버 쪽 코드로 막는다.

| 리스크 | 가드레일 |
| --- | --- |
| 사실 오류·환각 | 수치는 실험 데이터나 출처가 있어야 쓸 수 있다. `check_quality`가 본문 수치를 실험 CSV와 대조한다 |
| 비용 폭주 | 일·월 예산 상한, 사이클당 최대 툴 호출 수를 두고, 넘으면 즉시 중단하고 알린다 |
| 프롬프트 인젝션 | RSS·트렌드 등 외부 텍스트는 데이터로만 다룬다. 발행은 gated 툴이라 외부 텍스트가 직접 발행을 일으킬 수 없다 |
| 저품질·스팸 판정 | 하루 최대 1개, AI 작성 표시, 오리지널 데이터 중심으로 쓴다 |
| 저작권 | 외부 글은 짧게 인용하고 원문을 링크한다. 이미지는 직접 만든 측정 그래프만 쓴다 |
| 광고 표시 | 제휴 링크나 협찬이 들어가면 글 상단에 광고임을 표시한다 (표시광고법) |
| Pi 장애·SD 손상 | git 백업, 외부 업타임 모니터, Cloudflare Pages 대기 미러로 대비한다 |
| 외부 공격 | Tunnel만 쓰므로 인바운드 포트를 열지 않는다. 대시보드는 접근을 제한하고, MCP에 셸 툴을 두지 않는다 |
| 실험 중 과열·메모리 부족 | CPU 온도 상한을 넘으면 실험을 중단한다. 실험 서비스에는 메모리 상한(MemoryMax)을 걸어 SSH와 블로그를 지킨다. 블로그 서빙이 우선이다 |
| 레포 공개로 인한 유출 | 비밀값·원본 로그·미발행 초안은 `.gitignore`로 git에서 뺀다. 커밋 직전 pre-commit 훅이 금지 경로와 키 패턴(gitleaks)을 막고, GitHub Secret Scanning·Push Protection이 push 단계에서 한 번 더 막는다 |
