# unattendant.dev — Edge AI 연구 주제 논의 정리

> 하드웨어: Raspberry Pi 4B (4GB), Raspberry Pi Camera Module 2 (NoIR 아님)
> 작성일: 2026-10-06

## 1. 대원칙

- 통계를 계속 올리려면 **시간이 지나면서 바뀌는 변수**가 있어야 함. 고정된 하드웨어 벤치마크는 포스팅 1편이면 끝남.
  - 바뀌는 변수: 신모델 출시, 조명/계절/온도, 런타임 버전, 실환경 데이터
- 측정 방법(프롬프트 세트, 테스트셋, 지표)은 **한 번 정하면 고정**해야 회차끼리 비교가 됨.
- Pi CPU로만 낸 수치는 "산업 기준"이 아니라 **참고용·취미용 벤치마크**라고 글에 명시.

## 2. 확정된 방향: 두 축 운영

| 시리즈 | 성격 | 주기 |
|---|---|---|
| LLM 시리즈 (Qwen, Gemma, Llama, Phi 등 소형 모델) | 이벤트성 | 신모델 출시 시 |
| 비전 시리즈 (YOLO 등) | 정기물 | 주간 리포트 |

- 기계적으로 번갈아 올리기보다 **정기물(비전)과 이벤트물(LLM)을 섞는** 구조.
- 4GB Pi에서 두 실험을 **동시에 돌리지 않음**. 메모리/CPU 경합으로 측정값이 오염되기 때문. 시간대를 분리할 것 (예: 비전은 낮, LLM 벤치는 새벽).
- 온도·클럭·전력 로그는 두 실험에 **공통으로** 수집.

## 3. LLM 시리즈

### 소형 LLM이란
- Qwen(알리바바), Gemma(구글), Llama(메타), Phi(MS)는 **오픈 웨이트 모델 패밀리**. 엣지 전용은 아니고, 패밀리 안의 작은 버전이 엣지에서 돌아감.
- 모델 파일(GGUF)을 받아서 llama.cpp나 Ollama로 실행. 프롬프트를 넣으면 Pi CPU가 직접 답을 생성함. 오프라인이고 API 비용 0원.
- Pi 4B 4GB 현실: 0.5B~3B 모델의 4bit 양자화 버전이 한계. 품질은 ChatGPT보다 확실히 낮음.

### 측정 항목
- tokens/s, TTFT, 메모리 사용량, 간단한 품질 점수
- 양자화 수준별 비교 (Q4_K_M / Q5 / Q8)

### 현장 맥락
- 온디바이스 LLM의 실제 용도는 범용 챗봇보다 **좁은 작업**: 요약, 분류, 자연어 → 구조화 명령(function calling).
- 주요 시장은 스마트폰 AP와 차량용 SoC(NPU 탑재). Pi급 LLM 실서비스는 드물고 대부분 PoC 단계.
- 실험 아이디어: **음성/텍스트 명령 → 차량 제어 JSON 변환**의 정확도와 지연시간 (NPU 연구, 차량 미들웨어 경험과 연결됨)

## 4. 비전 시리즈

### 4-1. 내 방 고정 카메라 × 조명 변화 (메인)
- 카메라 고정, 10~15분 간격으로 자동 촬영
- 고정 물체(의자, 노트북, 모니터, 컵, 책)는 정답 라벨을 1회만 달고, 이후 recall과 confidence를 자동 계산
- 조도는 이미지 평균 밝기로 대체
- 콘텐츠: 시간대별 탐지율, 역광·해질녘·형광등 조건별 놓치는 물체, 소등 시 실패(NoIR 아님)

### 4-2. 개인 고정 벤치마크로 신모델 재평가
- 쌓인 이미지를 개인 테스트셋으로 사용
- 새 모델이나 런타임이 나올 때마다 정확도, FPS, 전력 비교
- 런타임 비교 후보: PyTorch, ONNX Runtime, TFLite(LiteRT), ncnn, FP32 vs INT8

### 4-3. COCO 클래스 한계 → 파인튜닝
- 키보드, 멀티탭처럼 COCO에 없는 물체를 직접 라벨링하고 파인튜닝해서 전후 비교

### 4-4. GPIO end-to-end 지연·jitter 측정 (차별화 포인트)
- 대부분의 Pi 벤치 글은 "FPS 몇 나옴"에서 끝남 → **현실 사건 발생부터 제어 출력까지**를 측정
- 측정 방법:
  1. 출력 핀 A로 카메라 앞 LED ON (사건 발생 시점)
  2. 카메라가 LED를 인식하면 출력 핀 B 토글
  3. A→B 시간을 로직 애널라이저, 오실로스코프, 또는 STM32 타임스탬프로 측정
  4. 수백 회 반복 → 평균, p99, 히스토그램
- 소프트웨어 타임스탬프만 쓰면 카메라 노출~프레임 도착 지연이 빠지므로 외부 이벤트 방식이 필요
- 비교 모델:
  - 검출: YOLO nano급, NanoDet, MobileNet-SSD
  - 분류: MobileNet, EfficientNet-Lite
  - **AI 없는 베이스라인**: OpenCV 색상 임계값. 전체 지연 중 모델이 차지하는 비중을 보여줌
- 처음엔 LED로 시작 (물체를 서보로 가리는 방식은 복잡함)

### 주의
- 방 사진 공개 시 모니터 화면, 우편물, 창밖 풍경, 본인 노출 확인
- person 클래스가 잡힌 프레임은 업로드에서 제외
- 원본보다는 탐지 결과 이미지와 통계 위주로 공개

## 5. Pi와 산업 현장

- 산업용 Pi는 주로 게이트웨이, 데이터 수집, HMI, 간단한 제어 용도 (GPIO, UART, I2C, SPI, CAN)
- GPIO와 Edge AI는 별개가 아니라 **센서 → 추론 → 액추에이터** 파이프라인의 일부
- CPU로도 충분한 작업: 진동/전류 이상 감지, 소형 분류, 저해상도 비전
- 양산품은 NPU 내장 SoC가 주류 (NXP i.MX 8M Plus, RK3588, Jetson Orin Nano), 또는 Pi + 가속기
- 가속기 연결: Pi 4B는 USB(Coral 등), Pi 5와 CM4는 PCIe(Hailo)
- 확장안: 나중에 CPU vs 가속기 비교로 키우면 실무에 더 가까움

## 6. 보류 및 부가 아이디어

### LLM API 지연·가격 트래커
- 구독(ChatGPT Plus 등)과 API는 별개라 **구독은 필요 없음**. API는 종량제.
- 비용(가정치): 10분 간격, 출력 200토큰 기준으로 저가 모델은 월 1달러 미만, 플래그십은 월 수~십수 달러. 시작 전 실제 가격표로 재계산 필요.
- 비용 줄이는 법: 저가 모델은 촘촘하게, 플래그십은 하루 몇 회. TTFT용은 출력 20~50토큰. spending limit 설정. 무료 티어는 레이트리밋 왜곡 표시.
- 가격 변화 추적(가격 페이지 크롤링)과 장애 기록(status 페이지)은 무료.
- 한계: Artificial Analysis, OpenRouter가 이미 하고 있음 → 차별점은 **한국 회선 실측치**

### 기타
- 블로그 자체 운영 통계 (AI가 24시간 운영하는 블로그의 비용·트래픽·SEO) → 메타 콘텐츠, 바이럴 잠재력 높음
- 발열·스로틀링·전력 장기 로깅 (쿨러 유무, 계절별, J/inference) → 두 시리즈의 공통 로그로 흡수
- 소형 LLM 서빙 스케줄링 (FCFS / SJF / MLFQ) → 포트폴리오 가치는 높지만 대중성은 낮음
- 네트워크 품질, 공기질 로깅 → 쉽지만 남들이 볼 이유가 약함
