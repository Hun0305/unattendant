# 과제 세트 llm-tasks-v1

소형 LLM의 품질을 재는 한국어 100문항이다. 설계는 [docs/experiments.md](../../../docs/experiments.md) 6절에 있다.

**상태: 초안, 운영자 검수 전 (2026-10-14).** 검수가 끝나기 전에는 결과를 글에 쓰지 않는다. 검수가 끝나면 이 줄을 "검수 완료(날짜)"로 바꾸고, 그 뒤로 v1은 고치지 않는다. 고칠 게 생기면 v2를 만든다.

| 과제 | 파일 | 문항 | 채점 |
| --- | --- | --- | --- |
| T1 명령 → JSON (차량 제어) | `t1_command.jsonl` | 30 (동작 하나 15, 여럿 10, 할 수 없는 요청 5) | 파싱, 스키마, 정답(동작 묶음과 reject, 순서 무관) |
| T2 의도 분류 (쇼핑몰 문의) | `t2_intent.jsonl` | 30 (라벨 5개 × 6) | 라벨이 정확히 하나 나오고 정답과 같음 |
| T3 정보 추출 (약속 문자) | `t3_extract.jsonl` | 20 | date, time, place, people 넷 다 맞음. 항목별 정답 수도 남긴다 |
| T4 짧은 한국어 답 | `t4_answer.jsonl` | 20 | 필수 키워드 포함, 금지어 없음. 언어 이탈은 따로 센다 |

- `prompts.toml`: 과제별 지시문(system)과 예시 2개, 최대 토큰 수. 모든 모델에 같은 것을 쓴다.
- `score.py`: 채점 규칙. `python3 score.py`는 정답을 그대로 넣었을 때 모두 맞는지 확인한다.
- 문항과 정답은 이 블로그가 직접 만들었다. 실제 인물·업체와 관계없다. 라이선스는 CC0다.

## 검수할 것

문항마다 아래를 본다. 고칠 문항은 id와 이유를 적어 주면 반영한다.

1. **정답이 맞나**: 지시문 규칙대로 하면 정답이 하나로 정해지는가. 예: T1의 "위치를 말하지 않으면 all/driver", T3의 "인원이 없으면 null"
2. **애매하지 않나**: 사람이 봐도 둘 이상으로 읽히면 고치거나 뺀다. 예: T2 "반품 수거 기사님이 안 오셨어요"는 배송이 아니라 교환·반품으로 정했다
3. **허용 답이 충분한가**: T3 장소의 대체 표기(`place` 목록), T4 키워드의 다른 표기(예: "열두 살", "12살")
4. **너무 쉽거나 어렵지 않나**: 1B급 모델 기준으로 다 맞히거나 다 틀리는 문항만 있으면 차이가 안 보인다

## 알려진 한계

- 문항 수가 적다. 30문항에서 1~2문항 차이는 우연 범위라 순위를 매기지 않는다.
- T4는 키워드로만 채점해서, 키워드가 들어간 틀린 문장도 맞게 칠 수 있다. 금지어는 반대 오답을 잡을 때만 한 문항(t4-11)에 썼다.
- 공개된 문항이라 나중에 나온 모델이 학습했을 수 있다.
